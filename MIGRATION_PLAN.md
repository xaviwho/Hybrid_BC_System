# Bring-Up Plan — rebuilding the measurement stack in place

**Host: Windows + WSL2 `Ubuntu-22.04` — the existing distro on this machine.**
(§0 records the alternatives considered; §11 records the decisions.)

> **Corrected 2026-08-18.** An earlier draft of this plan opened by stating the
> `Ubuntu-22.04` distro *had been deleted*, and was written as a migration to a
> second machine. **That premise was wrong.** The distro is present and healthy
> (Ubuntu 22.04.5 LTS, WSL 2, ext4 with ~950 GB free). What was actually lost is
> its *contents*: `/root/fabric-clean`, `/root/hybrid-fabric` and
> `/root/orbit-venv` are gone. So this is a **runtime rebuild in place**, not a
> migration — Phase A0 below is unnecessary, and the host-provisioning work is
> roughly fifteen minutes rather than several hours.

**Goal.** Bring the full stack up and produce the three
outstanding measurements — exp1 (latency/throughput), exp3 (gas), exp5
(exactly-once) — then get the results back into the repository.

**Why this is a rebuild, not a copy.** The distro survives, but the runtime
directories inside it do not: `/root/fabric-clean` (Fabric runtime **and its
crypto material**), `/root/hybrid-fabric` (chaincode source) and
`/root/orbit-venv` (the Python environment) are all absent — `/root` shows no
activity since July 2025. None of it can be copied because none of it exists. That is less bad than it sounds: Fabric's crypto material is
regenerated by `network.sh` on every `up`, so it was never worth migrating.

**What actually moves:** nothing between machines. The repository is cloned from
the Windows-side working copy onto ext4 inside the distro (§0.1), and the three
runtime directories are rebuilt from upstream sources.

## 0. Target OS — decided

| Target | Verdict |
|--------|---------|
| Native Linux (Ubuntu 22.04) | Technically preferred — removes four of six historical failure modes. **Not chosen.** |
| **Windows + WSL2 Ubuntu-22.04** | **← CHOSEN**, and already present. It is what the last successful run used. Reintroduces the WSL-specific hazards in §7, all of which are documented and mitigable. §7.1 is **mandatory**, not advisory. |
| macOS | **Not viable as-is.** Fabric's `network.sh` and the pinned `2.5.0`/`1.5.5` images work, but the repo's Fabric binaries are Linux ELF and `fabric_client.py` shells out to the `peer` CLI. Apple Silicon additionally needs `linux/amd64` emulation. A port, not a migration. |

### 0.1 The one decision that neutralizes the biggest WSL risk

`STACK_BRINGUP.md` was written against the **old** host, where the repo lived at
`/mnt/e/Hybrid_BC_System` — a drvfs-mounted **FAT32 stick**. That single fact is
the root cause of §7.1 (the outbox WAL guard), because drvfs cannot support the
shared-memory file and POSIX advisory locking that SQLite WAL requires.

**On the new machine, clone the repo into the WSL ext4 filesystem, not `/mnt/*`.**

```
OK     /root/Hybrid_BC_System         ext4, inside the distro  — WAL works
WRONG  /mnt/c/Users/<you>/Hybrid_BC   drvfs over NTFS          — WAL refused
WRONG  /mnt/e/Hybrid_BC_System        drvfs over FAT32         — the old layout
```

This does not make §7.1 optional — still set `OUTBOX_DB` explicitly — but it
turns the guard from a thing that *will* bite you into a backstop.

> **Path substitution warning.** Every path in `STACK_BRINGUP.md` reads
> `/mnt/e/Hybrid_BC_System/...`. Following it verbatim on the new machine
> recreates the FAT32 layout and reintroduces the WAL failure. Throughout §4 and
> §5 below, read `$REPO` for `/mnt/e/Hybrid_BC_System`.

## 4. Phase D — bring the services up

Follow **[STACK_BRINGUP.md](STACK_BRINGUP.md) §1–§5**, substituting `$REPO` for
every `/mnt/e/Hybrid_BC_System` (§0.1). It has the exact commands, health checks
and failure table, and it is current as of `489b3d41`. Deltas for a fresh WSL
machine:

1. **§2 Ganache** — the "must run **inside WSL**" caveat **applies**. A Ganache
   started on the Windows side is not reachable from the distro
   (`BRINGUP_STATUS.md`). Keep `--networkId 1337` and `--wallet.deterministic`.
2. **§3 contract** — the artifact carries 18 stale network entries and a dead
   address. Optionally prune (`networks = {}`) before `truffle migrate --reset`
   so the file stays readable.
3. **Paths** — §1's mount check (`ls /mnt/e/...`) is obsolete; the repo is on
   ext4 now. `df -T $REPO` from Gate B replaces it.

**Suggested order, easiest-first**, so a failure is diagnosed against the
smallest possible surface:

| Step | Service | Gate |
|------|---------|------|
| D1 | Ganache (inside WSL) | `eth_chainId` -> `0x539` |
| D2 | Contract deploy | §3 resolver check prints an address and non-zero code size |
| D3 | **exp3 (gas)** — run it now | 27 real transactions, exit 0 |
| D4 | Fabric | 8 containers + `peer chaincode query` round-trip |
| D5 | Policy engine | `/health` returns `policy_version` |
| D6 | Orchestrator | `/health` shows `ethereum_connected`, `contract_addr`, ext4 `outbox_db`; `/outbox_stats` shows `relay_running: true` |
| D7 | Smoke test | one ingest -> **202** -> `/anchor_status` -> `delivered` with `queue_wait_ms` + `anchor_ms` |

**Running exp3 at D3 is deliberate.** It needs only Ganache and the contract, so
it banks one of the three outstanding measurements before you touch Fabric —
which is the part most likely to fight you.

### Gate E — what success looks like

```
consolidate_results.py exits 0
  not_measured: []                        <- empty. exp1/exp3/exp5 all admitted
  metrics: run_contract_addr present      <- positive proof of one deployment
  kind_counts: measured > 8
```

**Three ways this legitimately fails, all of them the system working:**

| Signal | Meaning |
|--------|---------|
| exp1 exits **2** | Reconciliation gate failed — observed TPS disagrees with `concurrency / mean_ack_latency`. Writes `exp1_latency_real.FAILED.json`, records no throughput. Investigate; do not rerun until explained. |
| Orchestrator refuses to start | Either a stale contract (no bytecode) or a non-WAL outbox. Both deliberate. See §7.1, §7.2. |
| consolidator exits non-zero | Either an untagged metric, or a **contract address mismatch** across exp1/exp3/exp5 — meaning they did not all use one deployment. Redeploy, restart the orchestrator, rerun all three together. |

**Do not read an empty `not_measured` as success on its own.** Confirm
`run_contract_addr` is present. If it is missing, the cross-check did not run.

## 7. Risk register

### 7.1 The outbox WAL guard — **MANDATORY on WSL**

`OUTBOX_DB` defaults to the orchestrator package directory. Cloning to ext4
(§0.1) means that default is *probably* fine now — but do not rely on it. If the
repo ever sits on `/mnt/*`, SQLite silently declines WAL and `Outbox.__init__`
raises rather than run without it:

```
RuntimeError: outbox at '...' is in journal_mode='delete', not 'wal'.
```

WAL needs a shared-memory `-shm` file and POSIX advisory locking; drvfs provides
neither.

**Always set `OUTBOX_DB=/root/orbit-state/outbox.db` explicitly.** Verify:

```bash
sqlite3 /root/orbit-state/outbox.db 'PRAGMA journal_mode;'   # must print: wal
df -T /root/orbit-state | tail -1                            # must print: ext4
```

### 7.2 Contract address

Ganache starts with fresh state, so the contract must be redeployed and the old
address (`0xe78A0F7E598Cc8b0Bb87894B0F60dD2a88d6a8Ab`) is dead. The orchestrator
now **refuses to start** if the resolved address holds no bytecode. Always:
redeploy -> verify -> *then* start the orchestrator. Restart the orchestrator
after any redeploy — it resolves once at import.

### 7.3 Fabric CA enrolment

The single most likely failure. Mitigations, in order: use `/root/fabric-clean`
(pristine) not the repo copy; pass `-i 2.5.0 -cai 1.5.5` on **both** `up` and
`createChannel`; if enrolment hangs, `./network.sh down` and start clean rather
than retrying in place.

### 7.4 Port conflicts

5001 was occupied by an unrelated service on the current machine, which is why
the policy engine runs on **5011**. Check the new host before assuming — and note
that on WSL2 a **Windows-side** process can occupy a port the distro then cannot
bind, which `ss` inside the distro will not show:

```bash
ss -lptn 'sport = :5001 or sport = :5002 or sport = :8545 or sport = :7051'
```

```powershell
netstat -ano | findstr "5001 5002 8545 7051"    # Windows side, if the above looks clear
```

### 7.5 Results divergence — pick one measurement host

`experiments/results/` is now git-tracked. If two working copies both run
experiments, they will conflict on `RESULTS.json`.

With the rebuild happening in place there is only one *machine*, but there are
now two *clones* of the repo on it — the Windows-side copy and the WSL copy at
`$REPO`. The rule carries over unchanged:

**Rule: `/root/Hybrid_BC_System` inside the distro is the measurement copy.** The
Windows-side copy must not run experiments or regenerate `RESULTS.json` until the
WSL copy's results are committed and merged back.

Local regenerated results that predate this run are parked on the
`wip/pre-phase3-backup` branch, deliberately out of the way.

### 7.6 Timing measurements and machine load

exp1 and exp4 are latency experiments. Run them on an otherwise idle machine —
no builds, no other containers. On WSL2 this includes the **Windows side**: close
anything heavy, and be aware that the default dynamic-memory `vmmem` behaviour
can throttle the distro. Consider pinning memory in `%UserProfile%\.wslconfig`:

```ini
[wsl2]
memory=8GB
processors=4
```

Different hardware will produce different absolute latencies, which is expected
and fine, but they must be internally consistent within one run.
